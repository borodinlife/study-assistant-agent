# Помощник по учёбе (`study-assistant-agent`)

## Назначение агента
Консольное приложение для учёта учебных заданий студента. Программа позволяет добавлять лабораторные, курсовые и домашние работы по дисциплинам, просматривать общий список задач или фильтровать их по предмету, отмечать выполнение работ и удалять неактуальные записи.

## Технологический стек
- **Редактор кода / IDE:** Visual Studio Code
- **Язык программирования и версия:** `Python 3.15.1`
- **Среда выполнения:** интерпретатор `CPython`, изолированное виртуальное окружение `venv` (`.venv`)
- **Менеджер зависимостей:** `pip` (зависимости зафиксированы в файле `requirements.txt`)
- **Используемые библиотеки:** стандартная библиотека Python (`json`, `pathlib`)
- **Средства хранения данных:** оперативная память (`list[dict]`) с автоматическим сохранением состояния в локальный файл формата `JSON` (`tasks.json`)
- **Тестирование и покрытие:** `pytest`, `pytest-cov`
- **Отладчик:** встроенный отладчик VS Code для Python (`debugpy` / `pdb`)
- **Линтер:** `Ruff` (`ruff check`)
- **Форматтер:** `Ruff` (`ruff format`)

## Структура проекта
- `main.py` — точка входа в приложение: цикл чтения команд, разбор аргументов, валидация пользовательского ввода и вывод данных в консоль.
- `tasks.py` — модуль бизнес-логики: функции добавления, фильтрации, отметки выполнения и удаления заданий в памяти.
- `storage.py` — модуль файлового хранилища: загрузка и сохранение состояния в `tasks.json`, обработка первого запуска и ошибок чтения/записи (`StorageError`).
- `tests/` — автоматические модульные тесты (`test_tasks.py`, `test_storage.py`).
- `requirements.txt` — список зависимостей проекта для воспроизводимой установки окружения.
- `.gitignore` — список исключений Git (`.venv`, `__pycache__`, `tasks.json`, `.coverage`, `htmlcov/`).

## Подготовка окружения и запуск

1. Клонировать репозиторий и перейти в каталог проекта:
   ~~~powershell
   git clone https://github.com/borodinlife/study-assistant-agent.git
   cd study-assistant-agent
   ~~~
2. Создать и активировать виртуальное окружение:
   ~~~powershell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ~~~
3. Установить зависимости из файла `requirements.txt`:
   ~~~powershell
   pip install -r requirements.txt
   ~~~
4. Запустить приложение:
   ~~~powershell
   python main.py
   ~~~

## Доступные команды и штатное завершение
- `add <предмет>; <название>; <срок>` — добавить новое учебное задание (аргументы разделяются точкой с запятой `;`).
- `list` — показать все сохранённые задания и их текущие статусы.
- `list <предмет>` — показать задания только по указанной дисциплине (без учёта регистра).
- `done <id>` — перевести задание с указанным числовым идентификатором в статус `выполнено`.
- `delete <id>` — удалить задание по его числовому идентификатору.
- `help` — вывести справочную информацию со списком команд и их назначением.
- `exit` — штатно завершить работу приложения (также поддерживается выход по сочетанию клавиш `Ctrl + C`).

## Способ и момент сохранения данных
Состояние приложения хранится в локальном файле `tasks.json` в формате JSON (массив объектов с полями `id`, `subject`, `title`, `deadline`, `status`). За работу с файлом отвечает модуль `storage.py` (используется `pathlib.Path` и контекстный менеджер `with`).
- **Восстановление:** выполняется при запуске приложения функцией `load_storage()`. При первом запуске (если файла `tasks.json` ещё нет) возвращается пустой список `[]`. Если файл повреждён или имеет неверный формат, выбрасывается `StorageError`, приложение сообщает об ошибке и запускается с пустым списком.
- **Сохранение:** выполняется автоматически после каждой операции, изменяющей состояние (`add`, `done`, `delete`), с помощью функции `save_storage()`. Это гарантирует сохранность данных даже при внезапном закрытии программы.

## Автоматические тесты и покрытие кода
Для тестирования бизнес-логики и хранилища используются `pytest` и `pytest-cov`. Тесты хранилища изолированы от пользовательских данных с помощью встроенной фикстуры `tmp_path`.

- Запуск всех автоматических тестов:
  ~~~powershell
  python -m pytest
  ~~~
- Запуск тестов с измерением покрытия строк кода (без учёта пользовательского интерфейса `main.py`):
  ~~~powershell
  python -m pytest --cov=tasks --cov=storage --cov-report=term-missing
  ~~~

## Проверка качества кода (линтер и форматтер)
Для статического анализа и форматирования кода используется инструмент `Ruff`.

- Запуск линтера:
  ~~~powershell
  ruff check .
  ~~~
- Проверка соответствия кода правилам форматтера (без изменения файлов):
  ~~~powershell
  ruff format --check .
  ~~~
- Автоматическое форматирование кода:
  ~~~powershell
  ruff format .
  ~~~
